# content — data the sim and game read

Plain JSON authored from the design canon in `docs/factions/`. The faction files are the source; these files are the machine-readable subset. All files carry `schemaVersion`.

| Folder | Holds |
|---|---|
| `units/` | one file per unit — see the schema below (`schemaVersion: 2`) |
| `scenarios/` | `{schemaVersion, seed, ticks}` (+ units/spawns/commands as `sim/units`, `sim/orders` land) |
| `buildings/` | one file per structure — schema below (`schemaVersion: 1`) |
| `maps/` | typed tile maps (`schemaVersion: 1`): `rows` of `.` land, `~` water, `#` cliff, `=` bridge, plus `features` (mains, Seams, radars, rig, resource `field`s, …). Generated by `tools/mapgen`, never hand-edited. Scenarios embed the same rows as `map.terrain` (T25; the sim reads tiles per cell), and may also carry `blocked` rects [x0,y0,x1,y1] (hand-written test maps) and `causeways` (T26: lists of [x, y] land cells that are destructible, numbered after the `=` bridges). |

## `units/` schema (v2)

A unit file has three parts, and the split is the point: **identity is canon** (straight from the faction files, trustworthy), **`stats` and `weapon` are provisional** (untuned placeholders until the combat sim + `tools/scenario` tune them, MBT mirror first — `docs/factions/counter-matrix.md`). Never treat a `stats`/`weapon` number as balanced; do treat identity as fixed.

### Identity — required, canon-backed

| Field | Type | From canon | Notes |
|---|---|---|---|
| `schemaVersion` | int | — | `2` |
| `id` | string | — | kebab-case, unique across all factions |
| `name` | string | faction file | display name |
| `faction` | enum | faction file | `coalition` \| `hegemony` \| `ascendant` |
| `role` | string | unit table | `mbt`, `basic-infantry`, `scout`, `harvester`, `engineer`, `anti-armor`, `anti-air`, `artillery`, … |
| `tier` | int | tier table | `1` \| `2` \| `3` |
| `builtFrom` | string | building table | producing building id (`vehicle-bay`, `barracks`, …) — the prerequisite |
| `cost` | int | unit table | credits (faction-adjusted value as written in the faction file) |
| `buildTimeSeconds` | number | unit table | ×20 = ticks at 20 t/s |
| `armor` | enum | `Armor / Attack` | `infantry` \| `light` \| `heavy` \| `air` \| `structure`; naval extension `light-naval` \| `heavy-naval` \| `submerged` (`counter-matrix.md`) |
| `domain` | enum, optional | unit text ("hovers", "walks ashore") | `hover` for amphibious units (Skimmer, Ripple, Sever-class). Absent = from armor (T25): `air` flies, the naval armors sail, the rest walk. Also accepts `land` \| `naval` \| `air` |

### `stats` — required object, **provisional values**

| Field | Type | Notes |
|---|---|---|
| `hp` | number | untuned; faction HP modifier is *already* baked into the value, not applied at load |
| `speed` | number | world cells / second (`0` for immobile) |
| `sight` | number | vision radius in cells |

### `weapon` — optional object (omit for non-combat units: harvester, engineer, pure support)

| Field | Type | From canon | Notes |
|---|---|---|---|
| `damageType` | enum | `Armor / Attack` | `small-arms` \| `autocannon` \| `ap` \| `explosive` \| `missile` \| `energy`; naval extension `naval-gun` (shares the AP column) \| `torpedo` (`counter-matrix.md`) |
| `damage` | number | — | **base** damage, pre-matrix; final = `damage × matrix_cell` (`counter-matrix.md`). Provisional |
| `range` | number | unit table where stated | cells (e.g. Coalition MBT 12); provisional otherwise |
| `cooldownTicks` | int | — | ticks between shots; provisional |
| `description` | string | faction md "Produces / unlocks" and role columns | one short line (≤ 42 chars) on what it does, shown under the name in the build menu, on hover in the training panel and in tooltips; says "(not in yet)" / "(not armed yet)" where the sim lacks the behaviour. Buildings carry it too. Test: `DeployTests.Every_unit_and_building_says_what_it_does_in_one_short_line` |
| `targets` | string[] | `counter-matrix.md` (targeting) | subset of `["ground","air","sea"]` — which domains the weapon can engage *at all*, separate from the multiplier. Ships by type: corvettes, destroyers, subs and bombardment ships include `ground` (they hit the shore); AA cruisers are `air` only |

### `verbs` — optional flags (owned-verb applicability, `owned-verbs.md`)

Present only where canon says the unit has it: `marksOnHit` (Coalition — a weapon that marks the struck target), `marksAura` (Coalition — a radius Marking source: Comms Rig, Spotter Drone), `conscriptable` (Hegemony infantry), `phases` (Ascendant phase-capable, per `owned-verbs.md`). T29 live: aura sources also carry `markRadius` (cells; canon Comms Rig 8, Spotter Drone 7), and the Sapper `conscriptEffect: "detonate"`. Buildings may carry `verbs` too: `coalition-sensor-command` `{marksAura, markRadius: 14}` (and it gates the aura network), `hegemony-conscription-hall` `{conscriptionHall: true}` (the 50% refund zone). T28: the Weaver carries `cannotCapture` (it repairs, canon ascendant.md) and `repairsStructures` (mends its own side's buildings); the Mindbender carries `mindControl` (channels: controls units, takes buildings); `neutral-oil-derrick` (faction `neutral` = sim -1, category `offshore`, 2x2) carries `{oilIncome: 5, restoredByEngineer: true}` (credits per second to its owner; destroyed, it is a wreck until an engineer restores it). Ability verbs (our tuning; the sim reads them into `world/Abilities`): `phasesBetweenShots` (Phase Turret), `lineDamage` (Rift Node / Lance / Hull), `neverDepletes` (Cultivator), `shieldRadius` + `shieldPercent` (+ `shieldNavalOnly`: Anchor, Warden), `healRadius` + `healPerSecond` (Field Repair), `sabotages` (Operative), `hijacks` (Hijacker), `stealth`, `cloakRadius` (Mindbender), `detectRadius` (detectors, units and buildings), `radarRadius` (Seam Radar: vision only), `capacity` + `carries` (`infantry` / `ground`) with `garrison` (bunkers: passengers fire out) or `tunnel` (one shared hold per side), `teleport` (Teleport Node), `launches` + `wing` + `rebuildSeconds` + `launchRange` (carriers; the aircraft are units with role `carrier-aircraft`, `builtFrom` = the carrier, cost 0), `holdCapture` + `holdRadius` (the derrick rig), `chargeSeconds` + `strikeRadius` + `strikeDamage` (+ `strikePulses`, `strikeDelaySeconds`, `pulseGapSeconds`) for superweapons. Scenarios may list `ai: [factions]` (computer players, `sim/ai`). Scenarios may list `structures: [{building, at:[cellX, cellY]}]` (unowned map structures, spawned after the units); Tri-Point puts the derrick on the central rig. `neutral-bridge-hut` (1x1, neutral) is spawned by the sim at both ends of every bridge and causeway (not listed in scenarios): engineers sent there repair the bridge.

## `buildings/` schema (v1)

Same identity/provisional split as units. Structures are **faction-namespaced**: unlike units (whose names are globally unique), factions share building archetypes — Coalition and Hegemony both field a "Refinery" and a "Shipyard" — so a building `id` is **`<faction>-<name>`** (`coalition-refinery`, `ascendant-manifold`), and a unit's `builtFrom` is that prefixed id. That is the one link between the two folders; `builtFrom` on the unit is the source of truth for what a production building makes (a building does not re-list its units, to avoid drift).

### Identity — required, canon-backed

| Field | Type | From canon | Notes |
|---|---|---|---|
| `schemaVersion` | int | — | `1` |
| `id` | string | — | `<faction>-<name>`, kebab-case, globally unique |
| `name` | string | building table | display name (e.g. "Sensor Command") |
| `faction` | enum | — | `coalition` \| `hegemony` \| `ascendant` |
| `category` | enum | — | `construction-yard` \| `power` \| `economy` \| `production` \| `tech` \| `air` \| `naval` \| `defense` \| `superweapon` \| `logistics` \| `offshore` |
| `tier` | int | building table | `1` \| `2` \| `3` |
| `prereq` | string\|null | Prereq column | the building id required first; `null` for the Construction Yard (placed by deploying the faction MCV) |
| `cost` | int | building table | credits (faction-adjusted value as written) |
| `buildTimeSeconds` | number | building table | ×20 = ticks |
| `power` | int | Power column | economy.md mapping: `+`→+100, `−`→−20, `−−`→−50, `−−−`→−150, none→0 |
| `produces` | string[] | Produces/unlocks column | short slugs of what it builds or unlocks; the authoritative building→unit link is the unit's `builtFrom`, not this list |
| `requiresShore` | bool | `T1*` / "+ shore" | present & `true` for shipyards, coastal batteries, offshore platforms. T25: `naval` / `offshore` buildings stand wholly on water and need land beside them; a land building with it needs water beside it |

Optional `deploysTo` on a unit (T32, MCVs with role `mcv`): the construction-yard building id a `deploy` turns it into. Canon prices the MCV row at the yard's 2500 (`coalition.md` etc.); its unit build time (30 s) and stats are provisional.

Optional `footprint: [w, h]` (cells, provisional tuning — canon gives no sizes): when absent the sim uses a category default (`BuildingCatalog.DefaultFootprint`: 3x3 construction-yard/production/economy/naval/air/superweapon, 2x2 power/tech/logistics/offshore, 1x1 defense). Barracks and conscription hall override to 2x2.

Defense buildings carry a `weapon` block, the same shape as a unit's (`damageType`, `damage`, `range`, `cooldownTicks`, `targets`); our tuning, canon gives only the coastal batteries' ranges (28, Shore Gun 30). `verbs.marksOnHit` works on a building too (Precision Turret). Buildings without `weapon` never fire.

`stats.hp` is a provisional object (qualitative HP tier from the table → a placeholder number), same rule as units. Optional flags (`garrisonable`) where canon states them.

## Rules

- kebab-case ids; unit ids globally unique; building ids `<faction>-<name>` (see above).
- Numbers authored as decimals, converted to Fix64 at load. Authoring-only `FromDouble` is allowed (ADR 0003); never a runtime float in `sim/`.
- Identity fields come from the faction file — if you change one here, change it there in the same PR (they must not drift).
- Add or rename a field → bump `schemaVersion` and update the loader (when it exists) in the same PR.
- A `stats`/`weapon` change is a balance change → needs a balance scenario run once the combat sim exists (`tools/scenario`).

Change impact: `../map/effects/CONTEXT.md` — unit stats (balance), the counter matrix (armor/`damageType`), economy (cost/`buildTimeSeconds`), owned verbs (`verbs`).
